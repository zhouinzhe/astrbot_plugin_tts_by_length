# TTS 长短分流（astrbot_plugin_tts_by_length）

短句开口说，长文发文字：**短文本调用 TTS，长文本直接发文字。** 朗读前自动过滤链接、代码块、Emoji 等不适合读出来的内容。

**v2.0 新增「语音记忆」**：记下每条语音说了什么，别人引用这条语音时告诉大模型“被引用的是哪一句”，大模型也能知道自己最近发过语音。

仓库：https://github.com/zhouinzhe/astrbot_plugin_tts_by_length

## 使用
1. 插件管理 → 上传 ZIP 安装并启用。
2. AstrBot 自带 TTS：保持「启用文本转语音」开启并选好 TTS 提供商，但把「TTS 触发概率」设为 **0**（由本插件接管，否则长文本会被内置 TTS 再转一遍）。
3. 在插件配置里设置 `max_chars`（默认 80）。
4. 关闭流式输出，否则流式回复会跳过发送前钩子，TTS 不会触发。

## 朗读时过滤什么
- **链接**：`https://…`、`www.…` 不朗读；Markdown 链接 `[文字](url)` 只读文字；`![图](url)` 整体丢弃。
- **代码块**：含 ``` 代码块的回复默认整条发文字。
- **Emoji / 符号**：默认去掉，避免 TTS 读错。
- **@**：消息链里带 @ 组件，或正文里有 `@QQ号`、`[At:123456]`、`[CQ:at,…]` 时，整条发文字、不调用 TTS（`skip_if_at`）；关掉这个开关后，这些 @ 文本也会被过滤、不会被读出来（`strip_at_text`）。
- **自定义**：`custom_filter_patterns` 里填正则，例如 `（.*?）` 去掉括号动作。

长度按过滤后的文本计算，所以带一长串链接的短回复仍然会转语音。

## 链接怎么处理（url_action）
| 值 | 效果 |
|---|---|
| append_links（默认） | 语音不读链接，链接以文字跟在语音后面 |
| strip | 语音不读，链接直接丢掉 |
| send_text | 只要有链接，整条发文字、不转语音 |

## 其他配置
| 项 | 默认 | 说明 |
|---|---|---|
| enabled | true | 总开关 |
| max_chars | 80 | 超过就发文字；0 = 不限 |
| min_chars | 1 | 短于该长度不转语音 |
| trigger_probability | 1.0 | 短文本转语音的概率 |
| tts_timeout | 30 | TTS 超时秒数，超时自动发文字；0 = 不限时 |
| keep_text | false | 转语音时同时保留原文（此时不再单独追加链接） |
| only_llm_result | true | 只处理大模型回复 |
| dedupe_same_event | drop | 同一轮对话里内容相同的重复回复：drop 丢掉重复文字 / keep_text 保留文字不转语音 / off 不处理 |
| skip_if_at | true | 含 @ 时整条发文字、不转语音 |
| strip_at_text | true | 朗读时去掉 @QQ号 / [At:…] 等文本 |
| skip_platforms | [] | 跳过的平台名 |

过滤后没有可读内容（只有链接、只有 Emoji 等）时不转语音，保持原文。

## 语音记忆（v2.0）
**解决什么问题**：大模型自己发出的语音，对它来说只是一条没有内容的“语音消息”。有人引用这条语音时，框架传给大模型的引用内容是空的，它不知道被引用的是哪一句，也不知道自己发过语音。

**怎么做**
1. 每次转成语音时，把实际朗读的文本记下来，按聊天（群号 / 私聊对象）保存，落盘在 `data/plugin_data/astrbot_plugin_tts_by_length/voice_memory.json`，重启不丢。
2. 有人引用机器人的语音时，用 OneBot 的 `get_msg` 反查被引用消息的**真实发送时间**，对上记录，把“语音里说的是：「……」”补在这条用户消息后面。第一次识别成功后会记住消息 ID，之后再引用同一条是精确命中，不再调接口。
3. 两条语音时间太近、分不清时，**不猜**，把候选都列给大模型；没有记录（升级前发的、已过期的）时，明确告诉大模型“内容没有记录”，避免它编。
4. 对方的消息里提到“语音 / 声音 / 说话”等词时，会在系统提示词里补一段“你最近发过这几条语音”（`recent_mode`，默认只在提到关键词时补，平时不增加任何开销，也不会破坏提示词缓存）。

任何一步出错都只记日志、不影响正常聊天和语音发送。

| 项 | 默认 | 说明 |
|---|---|---|
| voice_memory | true | 总开关 |
| memory_persist | true | 保存到磁盘 |
| memory_size | 30 | 每个聊天最多记几条 |
| memory_keep_hours | 168 | 记录保留多久（小时） |
| inject_quote | true | 识别被引用的语音（也会补上框架没带上的机器人文字引用） |
| match_tolerance | 30 | 时间匹配容差（秒），服务器时钟和 QQ 差得多时调大 |
| recent_mode | keywords | keywords 提到关键词才补 / always 每次都补 / off 不补 |
| recent_count / recent_minutes | 3 / 30 | 补充最近几条、最近多少分钟内的 |
| recent_keywords | 语音、声音、… | 触发关键词 |
| quote_note_template / recent_note_template | 见配置页 | 补给大模型的说明文字，可按人设改写 |

**怎么确认生效**：让机器人发一条语音，再引用这条语音说句话。日志里应该有
- `已转为语音`（发语音时）
- `引用识别：命中语音记录（time）`（第一次引用）
- `引用识别：按消息 ID 命中语音记录`（再次引用同一条）

如果看到“拿不到被引用消息的时间”，说明 `get_msg` 没调通；看到“没有对应的语音记录”，说明那条语音是升级前发的或已过期。

**限制**
- 精确识别依赖 OneBot（QQ / NapCat）的 `get_msg`；其他平台只能用引用里自带的时间，未经验证。NapCat 的“上报自身消息”不是必需的，开不开都行。
- 升级前发的语音、别的插件或 AstrBot 内置 TTS 发的语音没有记录。内置 TTS 的触发概率请保持 0。
- 只识别机器人**自己**的语音；别人发的语音要读出内容需要语音转文字（STT），本插件不做。
- 记录按“聊天”保存，群聊开了会话隔离也不影响。
- 和之前一样：流式输出下发送前钩子不触发，TTS 和语音记录都不会生效。

## 群聊注意事项
- 只识别 `@数字ID`、`[At:…]`、`[CQ:at,…]` 和真正的 @ 组件；`@昵称` 这种没有固定边界的写法不会被识别，需要的话可用 `custom_filter_patterns` 自己加正则。
- 智能体（Agent）用 `send_message_to_user` 等工具直接发出的消息不经过发送前钩子，本插件管不到，它们始终是文字。
- 如果 AstrBot 全局开启了「回复时 @ 发送者 / 引用回复」，框架会在插件之后才加上 @ 和引用，插件看不到，语音是否能带上它们取决于平台。

## 同一轮对话去重
agent 先说一句话、调用工具（如 `search_memes` 选表情），工具跑完后又把同一句话说一遍时，两条回复会各走一次发送前钩子，转出两条语音。`dedupe_same_event` 会按「忽略标点和空白后内容相同」判断重复；重复回复里的文字会被丢掉，表情图片等其他内容保留，没内容可发就整条不发。内容不同的两条回复不受影响。想从源头避免，可以在人设提示词里加一句「用工具之后，最终回复不要重复已经说过的话」。
