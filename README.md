# Fish TTS优化

> 短句开口说，长文发文字。直连 [Fish Audio](https://fish.audio)，支持 S2 情绪标签，发文字时自动去标签。

- 🐟 **直连 Fish**：插件自己调用 Fish API，可走自建 Cloudflare Worker 反代，不依赖 AstrBot 的 TTS 设置
- 🎙️ **音色库**：保存多个音色 ID（可写备注），随时切换，重启不丢；插件页面里点一下就能试听
- 🖥️ **控制台页面**：在 AstrBot 网页里管理音色、试听，**全部设置**也都能改，手机上同样好用
- 🎭 **情绪标签**：`[happy]`、`[whispering]`、`[laughing]` 转语音时交给 Fish，发文字时自动去掉
- ✂️ **长短分流**：短回复转语音，长回复发文字；链接、代码块、Emoji、@ 自动过滤
- 🧠 **语音记忆**：记下每条语音说了什么，别人引用这条语音时告诉大模型

> 原名「TTS 长短分流」（`astrbot_plugin_tts_by_length`），v3.2 起改名为 **Fish TTS优化**，插件标识和仓库改为 `astrbot_plugin_fish_tts`。
> 从旧插件换过来：设置需要重新填一次；旧的语音记录在 `data/plugin_data/astrbot_plugin_tts_by_length/`，需要的话把 `voice_memory.json` 复制到 `data/plugin_data/astrbot_plugin_fish_tts/`。

## 工作流程

```
大模型回复 ──► 过滤（链接 / 代码 / Emoji / @）──► 判断长度
                                                    │
                    ┌───────────────────────────────┴───────────────┐
                 短（≤ 上限）                                    长 / 含 @ / 失败
                    │                                               │
        带情绪标签发给 Fish 合成                          发文字（自动去掉情绪标签）
                    │
              发送语音，并记入语音记忆
```

长度按**过滤之后、去掉情绪标签之后**的文本计算，所以带链接或标签的短回复仍然会转语音。

## 快速开始

1. 插件管理 → 上传 ZIP 安装并启用。
2. 打开插件设置 → **🐟 Fish 语音合成**，填 **API Key**（[Fish 控制台](https://fish.audio/app/api-keys)创建）。走自建反代就改**接口地址**。
3. 音色：不填就是 Fish 默认音色；想用自己的音色，管理员发 `/fish音色 添加 小克 音色ID`，再 `/fish音色 切换 小克`（见下面「音色库」）。
4. **模型**保持 `s2.1-pro`（免费开发者额度选 `s2.1-pro-free`）。情绪标签需要 S2 系列模型。
5. 关闭 AstrBot 的流式输出，否则流式回复会跳过发送前钩子，TTS 不会触发。

直连 Fish 时**不需要**在 AstrBot 里启用文本转语音或选 TTS 提供商。如果同时开着 AstrBot 自带的 TTS，把它的「触发概率」设为 **0**，避免对长文本再转一遍。

> **想继续用 AstrBot 自带的 TTS 提供商**：把「语音合成方式」改成 `astrbot`。情绪标签会原样交给那个提供商，是否生效取决于它发的是不是 S2 模型。

- **v3.2 → v3.3**：直接覆盖安装即可，设置和语音记录都沿用。
- **v3.0 或更早 → v3.1 及以后**：设置改成了分组显示，v3.3 起不再自动搬运旧的平铺设置，请到设置页重新确认一遍。

## 音色库
保存多个音色（名称 + 音色 ID + 备注），随时切换，不用每次进设置页改 ID。可以在**插件页面**里管理，也可以在聊天里用指令。数据存在 `data/plugin_data/astrbot_plugin_fish_tts/voice_library.json`，更新、重装插件都不会丢。

| 指令 | 说明 |
|---|---|
| `/fish音色 添加 名称 音色ID [备注]` | 保存一个音色；同名会覆盖（不写备注就沿用原来的）。音色 ID 可以直接贴音色页面地址（`https://fish.audio/m/…`）；备注不能有空格，长备注请在插件页面里写 |
| `/fish音色 列表` | 看已保存的音色，`▶` 是当前在用的 |
| `/fish音色 切换 名称` | 切换音色，下一条语音起生效；名称也可以换成列表里的序号 |
| `/fish音色 删除 名称` | 删除；删的是当前音色就回到默认音色 |
| `/fish音色 默认` | 不用音色库里的音色，改回设置页里的默认音色 |

- **添加 / 切换 / 删除 / 默认**只有管理员能用，`列表`所有人都能看。
- 名称不分大小写，不能有空格，不能是纯数字；最多存 50 个。
- 音色选择是全局的（所有聊天共用）。没选中音色库里的音色时，用设置页里的「默认音色 ID」；那个也没填就是 Fish 默认音色。
- 只在「语音合成方式」为 `fish` 时生效。

### 插件页面
在 WebUI 的插件管理里打开本插件的详情页，进入「控制台」页面（需要登录 Dashboard，所以不用再单独判断管理员）。顶部有两页：

**音色库**
- 添加、编辑（改音色 ID 和备注）、删除、切换音色、改回默认音色；名称相同会覆盖，备注留空会清掉原来的备注。
- **试听**：每个音色卡片上的「试听」、表单里的「试听这个 ID」（还没保存也能试），以及「试听当前在用的音色」。试听文字可以自己写，最多 200 个字，留空用默认的一句话；试听固定用 mp3，不受「音频格式」设置影响。
- 试听会真实调用 Fish 接口，和正常合成一样计费。声音出现在页面底部的播放条里，滚到哪里都看得到。

**设置**：本插件的全部设置项（基础、Fish 语音合成、高级参数、情绪标签、朗读过滤、语音记忆）都能在这里改，和 AstrBot 自带的插件设置页是同一份配置。
- 按分组折叠，可以搜索（比如搜「语速」「超时」「@」）；改过但还没保存的项左边有竖线，底部出现保存条，可以一键放弃。
- **保存后立即生效，不用重载插件**。整批校验：有任何一项不合法（范围不对、JSON 写错、正则无效……）就一项都不保存，并在对应位置标出原因。
- 当前用不上的项（比如关了「识别情绪标签」后的相关设置）会淡化显示并注明「未生效：…」，仍然可以改。
- 每项有「恢复默认」；数值项带范围，语速、音量、概率这类有滑块。
- **API Key 不会回显**：页面只告诉你「已设置（••••末四位）」；留空表示不修改，输入新的就是替换，也可以点「清除」。
- 设置页的「试听当前设置」：有没保存的修改会先保存再试听，方便边调语速边听。
- 页面里的数据也能在 AstrBot 自带的插件设置页看到；两边同时开着时，以后保存的为准。

## 情绪标签
Fish 的 S2 模型用方括号控制语气：`[happy] 今天天气真好`、`[sad][whispering] 我想你了`、`[laughing] 哈哈 笑死我了`。

| 场景 | 插件怎么处理 |
|---|---|
| 转语音 | 标签原样交给 Fish（全角 `［］` 换成半角；一条最多保留设定个数） |
| 算长度 | 标签不计入字数（`[excited][laughing] 哈哈` 只算 2 个字） |
| 发文字（太长、含 @、合成失败……） | 自动去掉标签；代码块和行内代码里的方括号不动 |
| 语音记忆、去重 | 按去掉标签的文本，`[happy] 好呀` 和 `[excited] 好呀` 算同一句 |
| 只有标签没有文字（如 `[laughing]`） | 不转语音；发文字时这条会被丢掉 |

**让大模型写出标签**，两种办法：
1. 开 **🎭 情绪标签 → 自动给大模型加标签使用说明**：插件每次请求把下面这段追加到系统提示词末尾（固定文本，不影响提示词缓存）。
2. 手动把它贴进人设，按角色改写，比如只保留会用到的标签。

```
【语音情绪标签】你的回复可能会被转成语音。想表达语气时，可以在句子开头加一个方括号情绪标签，例如：[happy] [sad] [angry] [excited] [surprised] [nervous] [calm] [curious] [sarcastic] [whispering] [soft tone] [laughing] [sighing]。
规则：标签只用英文，放在句首，每句最多 1~2 个；[laughing]、[sighing] 这类声音标签后面要跟上对应的拟声词（如“[laughing] 哈哈”）；语气平淡的句子不加标签，不要每句话都加；不要解释标签，也不要把标签当成对话内容。
```

**哪些方括号算标签**
- `any`（默认）：任何不超过 40 字的短方括号。S2 支持自然语言描述，`[softly laughing]`、`[轻声]` 也能用。`[CQ:…]`、`[At:…]`、`[1]`、`arr[i]`、Markdown 链接不会被误判。
- `whitelist`：只认 Fish 文档里的标签，再加上你在「额外标签」里补充的。

**标签速查**（完整列表见 Fish 文档 [Emotion Control](https://docs.fish.audio/developer-guide/core-features/emotions)）
- 情绪：`happy sad angry excited calm nervous surprised curious sarcastic worried embarrassed grateful disappointed hopeful lonely …`
- 语气：`whispering` `soft tone` `shouting` `screaming` `in a hurry tone` `emphasis`
- 声音：`laughing` `chuckling` `sighing` `sobbing` `gasping` `yawning` `clear throat` …
- 停顿：`break` `long-break`　强度：`slightly sad` `very excited` `extremely angry`

**Fish 官方建议**：标签放句首效果最好；每句一个主情绪，叠加不超过 3 个；声音标签后面写上对应的字；短文本别滥用。

**限制**
- 智能体（Agent）用 `send_message_to_user` 等工具直接发出的消息不经过发送前钩子，里面的标签会原样显示。可以在提示词里加一句"工具发送的消息不要加情绪标签"。
- 「自定义过滤规则」里别写会匹配 `[happy]` 这类方括号的正则，否则标签在被识别前就被删了。
- `any` 模式下，大模型写的 `[注意]`、`[笑]` 这类短方括号也会当标签（发文字时被去掉）。不想这样就用 `whitelist`。
- Fish 的 S1 模型用圆括号写法 `(happy)`，且将于 2026-12-31 下线；插件只处理方括号。

## 语音记忆是怎么工作的
**问题**：大模型自己发出的语音，对它来说只是一条没有内容的"语音消息"。有人引用这条语音时，框架传给大模型的引用内容是空的。

**做法**
1. 每次转成语音，把实际朗读的文本（**不含情绪标签**）记下来，按聊天保存。
2. 有人引用机器人的语音时，用 OneBot 的 `get_msg` 反查被引用消息的真实发送时间，对上记录，把"语音里说的是：「……」"补在这条消息后面。第一次识别成功后会记住消息 ID，之后精确命中，不再调接口。
3. 两条语音时间太近分不清时**不猜**，把候选都列出来；没有记录时明确告诉大模型"内容没有记录"，避免它编。
4. 对方提到"语音 / 声音 / 说话"等词时，会补一段"你最近发过这几条语音"。

这些补充说明作为**临时内容块**（`extra_user_content_parts` + `mark_as_temp()`）加在本轮用户消息后面：只参与这一次请求，不写进对话历史，也不改系统提示词，所以不会破坏提示词缓存。
任何一步出错都只记日志，不影响聊天和语音发送。

**怎么确认生效**：让机器人发一条语音，再引用它说句话。日志里应该有 `已转为语音`（带标签时会写"含 N 个情绪标签"）和 `引用识别：命中语音记录`。

**限制**
- 精确识别依赖 OneBot（QQ / NapCat）的 `get_msg`；其他平台只能用引用里自带的时间，未经验证。
- 升级前发的语音、别的插件或 AstrBot 内置 TTS 发的语音没有记录；只识别机器人**自己**的语音，别人发的语音需要 STT，本插件不做。
- 流式输出下发送前钩子不触发，TTS 和语音记录都不会生效。

## 群聊注意事项
- 只识别 `@数字ID`、`[At:…]`、`[CQ:at,…]` 和真正的 @ 组件；`@昵称` 没有固定边界，不会识别，需要的话用「自定义过滤规则」加正则。
- 如果 AstrBot 全局开了「回复时 @ 发送者 / 引用回复」，框架会在插件之后才加上它们，语音能否带上取决于平台。

## 排错
| 日志 / 现象 | 原因与办法 |
|---|---|
| `还没有填写 Fish API Key` | 填 Key，或把「语音合成方式」设为 `astrbot` |
| `Fish TTS 合成失败 … HTTP 401` | Key 不对；走反代时检查有没有原样转发 `Authorization` |
| `… HTTP 402` | Fish 账户余额不足 |
| `… HTTP 503` | Fish 繁忙；会按重试次数重试，仍失败就发文字 |
| `返回的不是音频` | 多半是反代 / 网关返回了错误页，日志里带响应开头；检查接口地址 |
| `Fish TTS 超过 N 秒未返回` | 网络慢或 Fish 繁忙，调大 TTS 超时时间 |
| 标签被念出来了 | 多半是模型不是 S2；检查「模型」（`astrbot` 方式下检查提供商用的模型） |
| 语音没有情绪变化 | 日志里没有"含 N 个情绪标签"：大模型没写标签，开自动加说明或把说明贴进人设 |
| 文字里出现了 `[happy]` | 这条消息没经过本插件（Agent 工具发的 / 被跳过的平台），见情绪标签的限制 |

### 定时任务 / 主动消息

AstrBot 的「定时主动任务」（以及大模型调用 `send_message_to_user` 工具发的消息）是工具直接发给平台的，**不走普通回复的流水线**，插件原来挂的 `on_decorating_result` 根本不会触发，所以以前这类消息既不转语音、也不去情绪标签。

v3.5.1 起改挂 `on_using_llm_tool`：在这个工具发出消息之前处理参数里的文字，规则和普通回复完全一样（长度、概率、链接、代码块……都照设置走）。
- 纯文字、符合条件 → 换成一段语音；不符合（太长、含代码、合成失败等）→ 保持文字并去掉情绪标签。
- 带图片 / 文件的消息只去标签，不转语音。
- 语音记忆记在**目标会话**下，所以对方引用这条语音时，大模型能查到它说了什么。
- 设置在「基础设置 → 处理定时任务等主动消息」，默认开启；关闭后这类消息原样发出。
- 需要 AstrBot 4.12.2 及以上（`on_using_llm_tool` 钩子）。如果 AstrBot 开了沙盒（Computer Use 沙盒）模式，工具可能找不到插件生成的语音文件——遇到这种情况请关掉这个开关。
- 看日志确认是否生效：转成语音时会有一行 `[fish_tts] 主动消息（send_message_to_user）… 已转为语音`。
